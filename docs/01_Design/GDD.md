# OEC: Open-EscapeCage 게임 기획서 (GDD)

- 버전: v0.2 (노션 초기 기획 v0.1 + 보완안)
- 엔진: Unreal Engine 5.6 / C++ + GAS
- 장르: 1인칭 선택형 서바이벌 탈출 (질문 퍼즐 + 탐험 + 전투)
- 목표 플레이 타임: 1회차 40~60분, 엔딩 수집용 다회차 플레이

표기 규칙
- **[원안]**: 노션 초기 기획 내용
- **[보완]**: 이번에 추가하거나 구체화한 내용 (확정 전 검토 대상)
- `> 논의 필요`: 아직 결정이 필요한 항목

---

## 1. 세계관 및 스토리

### 1.1 배경 [원안]
- 정체를 알 수 없는 우주선 내부에서 눈을 뜬다.
- 주인공은 왜 여기서 깨어났는지, 자신이 누구인지 모른다 (기억상실).

### 1.2 보완 설정 [보완]
- **우주선의 정체**: 죄수를 대상으로 "선택 실험"을 하는 궤도 감옥선 *EscapeCage*.
- **관리자 AI "WARDEN"**: 단말기 너머의 목소리. 질문을 내고, 플레이어를 칭찬하거나 비웃는다. 페이즈 1 끝의 "축하합니다, 탈출입니다" 연출을 하는 주체이자 게임 전체의 적대적 화자다.
  - 성격: 차갑고 장난스럽다. 정신력이 낮아질수록 말투가 노골적으로 악의적으로 변한다.
- **주인공의 정체 (진엔딩에서 공개)**: 후보 예시
  1. 주인공은 이 실험을 설계한 연구원이었다.
  2. 주인공은 이미 여러 번 이 실험을 반복한 피험자다 (다회차 플레이 자체를 설정에 녹임).
  > 논의 필요: 진엔딩 반전 방향 선택

### 1.3 전체 흐름
게임 시작 → **페이즈 1** (메인 방에서 질문, 전구 5개 점등) → 가짜 탈출 연출 → **페이즈 2** (복도와 닫힌 방 탐색) → **결말** (탈출 방 도달 = 노말 엔딩 / 숨겨진 문 = 진엔딩)

## 2. 핵심 시스템

### 2.1 1인칭 시점과 상호작용 [원안]
- 1인칭으로 우주선을 탐색하고, 근접/원거리 무기를 직접 들고 싸운다.
- 상호작용 키는 **E**.

### 2.2 단말기와 물리 2버튼 [원안]
- 단말기 화면은 마우스로 클릭하지 않는다. 게임 속 오브젝트인 **빨간 버튼 / 파란 버튼**을 직접 눌러서 답한다.

### 2.3 단말기 배치 [보완]
원안에 "방마다 놓인 질문 모니터"와 "메인 방에서만 질문"이 섞여 있어서 아래처럼 정리한다.
- **메인 단말기** (메인 방): 페이즈 1, 2 공통으로 쓰는 주 단말기. 미니맵과 문 선택 기능이 있다.
- **보조 단말기** (복도 2 입구, 일부 안전 방): 질문만 가능하다. 페이즈 2에서 메인 방까지 왕복하는 피로를 줄인다.
  > 논의 필요: 보조 단말기를 넣을지, 메인 방 왕복을 긴장 요소로 남길지

### 2.4 질문과 선택지 [원안]
**핵심 재미: 랜덤하게 나오는 두 선택지 중 하나를 고르는 "운과 상황 판단", 그리고 무의미 질문이 주는 밈 같은 공감.**

- 빨강/파랑 버튼에는 **고정된 의미가 없다.** "빨강 = 고위험 고수익" 같은 규칙이 없고, 매 질문마다 두 선택지가 화면에 글로 명확히 적혀 나온다.
- 질문은 스택이 다 찰 때까지 랜덤으로 계속 나온다.
- 질문 유형(스토리, 보너스, 패널티, 밸런스, 무의미)은 **내부 분류**다. 질문 풀의 등장 비율을 조절하는 용도이고, 플레이어에게 보여주지 않는다.

#### 선택지 예시 (원안 의도)
| 질문 | 빨강 | 파랑 |
|---|---|---|
| 둘 중에 고르시오 | 약한 몬스터 2마리 소환 | 강한 몬스터 1마리 소환 |
| 둘 중에 고르시오 | 체력 10 회복 | 앞으로 답변할 때마다 1% 확률로 스택 +1 |
| 둘 중에 고르시오 | 체력 20 감소 | 무작위 적 소환 |
| 둘 중에 고르시오 | 체력 30 감소 | 7% 확률로 즉시 사망 |
| 둘 중에 고르시오 | 50%: 스택 +1 / 50%: 체력 30 감소 | 그냥 넘어감 |
| 둘 중에 고르시오 | 방이 어두워짐 | 약한 적 2마리 소환 |
| 더 좋아하는 건? | 고양이 | 강아지 |
| 나는 하와이안 피자를 좋아한다 | 예 | 아니오 |

#### 선택지 효과 분류 (예시에서 정리)
| 분류 | 예 | 시스템 요구사항 |
|---|---|---|
| 즉시 스탯 변화 | 체력 ±, 정신력 ±, 스택 ± | 즉시 적용 |
| 소환 | 약한 몬스터 2마리, 무작위 적 | 천장 스폰구에서 스폰 |
| 아이템 지급 | 무기, 회복 아이템 | 천장 투하구에서 투하 |
| 확률 분기 | 50%로 A 아니면 B, 7% 즉사 | 결과 여러 개 중 가중치로 하나 선택 |
| 지속 효과 | 답변할 때마다 1% 확률로 스택 | 이후 답변마다 발동하는 패시브 |
| 환경 변화 | 방이 어두워짐 | 조명, 포스트 프로세스 제어 |
| 아무 일 없음 | 그냥 넘어감 | |
| 무의미 | 고양이 / 강아지 | 효과 없음, 선택만 기록 |

#### 질문지 작성 계획
- **기능 구현을 먼저 끝내고, 질문지는 나중에 한 번에 작성한다** (현재 보류).
- 그래서 지금 단계의 목표는 "어떤 선택지든 데이터만으로 표현할 수 있는 효과 시스템"을 만드는 것이다 (7.2 참고).
- [보완] **효과 선택지 자동 조합**: 효과 풀에서 두 개를 랜덤으로 뽑아 "둘 중에 고르시오" 질문을 자동으로 만든다. 선택지 문구는 효과 데이터에서 생성한다 ("체력 {N} 회복"). 효과 질문은 대량으로 손으로 쓸 필요가 없어지고, **손으로 쓰는 건 무의미(밈) 질문과 스토리 질문에 집중**할 수 있다.
- **패닉 상태**에서는 선택지 글자가 깨져 보여서 무엇을 고르는지 알 수 없다 → 원안의 "답을 찍어야 함".

### 2.5 스택(전구)과 맵 이동 [원안 + 보완]
- [원안] 스택을 채우면 닫혀 있던 문이나 복도 격벽이 열린다.
- 스택은 **페이즈별로 나뉜다.** 질문 결과로 얻은 스택은 현재 페이즈의 스택으로 들어간다.
  - 페이즈 1 스택 (전구): 메인 화면 오른쪽 전구 5개. 소모되지 않고 쌓이기만 하며, 5개가 모두 켜지면 메인 방 문이 열리고 페이즈 2로 넘어간다.
  - 페이즈 2 스택 (열쇠): 닫힌 방을 여는 데 쓴다. 단말기 미니맵에서 방을 골라 스택을 소모하고 연다.
  > 논의 필요: 페이즈 2 시작 시 열쇠를 0개로 시작할지, 기본 지급할지
- 스택은 선택지 효과로만 얻는다 (예: "50% 확률로 스택 +1", "답변할 때마다 1% 확률로 스택").
- [보완] **스택 보정(천장 시스템)**: 운이 나쁘면 스택이 안 쌓여 페이즈 1이 끝없이 늘어질 수 있다. N번(예: 4번) 연속으로 스택을 못 얻으면 다음 질문에 스택을 주는 선택지가 반드시 하나 들어가게 한다. 랜덤 재미는 살리고 최악의 경우만 막는다.

## 3. 플레이어 데이터

### 3.1 기본 스탯 [원안]
| 스탯 | 초기값 | 비고 |
|---|---|---|
| Health / MaxHealth | 100 / 100 | |
| AttackPower | 1.0 | **배율**로 사용. 최종 피해 = 기본 피해(무기 또는 몬스터 데이터) × AttackPower |
| Speed | 기본 이동 속도 | |
| Stamina / MaxStamina | 100 / 100 | 달리기, 점프 소모 (이미 구현) |

### 3.2 정신력 (Sanity) [원안]
- 시작값 80 (노멀 상단).
- 답변 1회당 -2 (보너스/패널티로 변동 가능).
- 체력이 30 깎일 때마다 -5.

| 구간 | 상태 | 효과 |
|---|---|---|
| 100 ~ 80 | 각성 | 최대 체력, 공격력, 이동 속도 버프 |
| 80 ~ 30 | 노멀 | 효과 없음 |
| 30 ~ 15 | 두려움 | 최대 체력 감소 |
| 15 ~ 5 | 공포 | 최대 체력, 이동 속도 감소 |
| 5 ~ 0 | 패닉 | 질문 화면이 깨져 보임 (답을 찍어야 함) |

### 3.3 정신력 보완 [보완]
- **0 도달 시**: "붕괴" 배드 엔딩. 정신력도 체력처럼 패배 조건이 된다.
- **회복 수단**: 정신력 회복 아이템(보급 방), 안전 방에서 휴식(1회 한정 +15), 일부 보너스 질문.
- **상태별 연출**: 두려움부터 화면 비네팅, 공포부터 환청과 글리치, 패닉에서 WARDEN 대사 왜곡.
- **수치 검증 (예상 페이스)**
  - 페이즈 1: 답변 약 12회 → -24 → 약 56
  - 페이즈 2: 답변 약 15회 + 피격 → -30 ~ -40 → 약 15 ~ 25 (두려움~공포)
  - → 후반으로 갈수록 압박이 커지는 곡선. 회복 아이템을 찾게 만드는 동기가 된다.
  > 논의 필요: 실제 플레이 테스트 후 감소량 조정

### 3.4 인벤토리 [원안]
- 꽉 차서 답답하지 않도록 여유롭게 (현재 구현: 20칸 + 퀵슬롯 5칸).

### 3.5 무기와 아이템 [원안]
| 분류 | 목록 |
|---|---|
| 근접 무기 | 칼, 방망이 등 |

## 4. 콘텐츠 설계

### 4.1 페이즈 1: 메인 방 [원안]
1. 메인 방에 갇힌 채로 수수께끼 질문에 답한다.
2. 메인 화면 오른쪽에 전구 5개가 있다.
3. 보너스와 패널티를 번갈아 받으며 전구 5개를 켠다.
4. 5개가 모두 켜지면 닫혀 있던 메인 방 문이 열린다.
5. 메인 화면에 "축하합니다, 탈출입니다" 문구가 뜬다.

[보완]
- 보너스 결과의 아이템은 **천장 투하구**에서 떨어지고, 패널티 결과의 몬스터는 **천장 스폰구**에서 떨어진다. 페이즈 1에도 전투가 생기고, 무기 사용법을 자연스럽게 익히는 튜토리얼이 된다.
- 첫 2~3개 질문은 고정된 튜토리얼 질문 (버튼 누르기 → 아이템 줍기 → 몬스터 처치).

### 4.2 페이즈 2: 복도 [원안]
1. 메인 방 문이 열리면 탈출인 줄 알았지만, 긴 복도와 닫힌 방들이 보인다.
2. "탈출입니다" 문구가 사라지고 약 올리는 문구가 뜨며 질문이 다시 시작된다.
3. 메인 방에서 질문에 답해 닫힌 방을 열 기회(스택)를 얻는다.
4. 질문 화면의 미니맵에서 열고 싶은 방을 고른다.
5. 닫힌 방은 보급 방, 위험 방, 다음 복도로 가는 문 중 하나다. 방 내용은 매번 랜덤이다.

### 4.3 엔딩 [원안 + 보완]
| 엔딩 | 조건 |
|---|---|
| 노말 엔딩 [원안] | 복도 2의 탈출 방 도달 |
| 진엔딩 [원안] | 숨겨진 문을 연다 |
| [보완] 진엔딩 조건 | 기억 조각 3개 수집 + 스토리 질문에서 일관된 선택 (`ChoiceHistory`로 판정) |
| [보완] 사망 엔딩 | 체력 0 |
| [보완] 붕괴 엔딩 | 정신력 0 |

> 논의 필요: 사망 시 처음부터 다시 할지, 페이즈 2 시작 지점에서 재시작할지

## 5. 레벨 디자인

### 5.1 방 타입 [원안]
| 구역 | 방 | 등장 시점 |
|---|---|---|
| 안전 구역 | 메인 방, 복도, 안전 방 | 메인 방은 처음부터 |
| 보급 구역 | 보급 방 (아이템) | 페이즈 2 |
| 위험 구역 | 위험 방 (적) | 페이즈 2 |
| 탈출 | 탈출 방 | 복도 2에 배치 |

### 5.2 메인 방 [원안]
- 페이즈 1 내내 머물고, 페이즈 2에서도 계속 쓰는 거점.
- 질문 화면과 버튼 2개가 있다.
- 천장에 아이템 투하구와 몬스터 스폰구가 있다.

### 5.3 복도 [원안]
- 페이즈 2부터 등장. 열린 문 앞으로 복도가 뻗어 있고 양옆에 닫힌 문이 4개씩, 복도 하나에 총 8개.
- 복도는 2개 (복도 1, 복도 2). 복도 1의 문 8개 중 하나가 복도 2로 가는 문이다.

### 5.4 원안의 우려점과 해결안 [보완]
원안 우려:
- 복도 2까지 랜덤 배치하면 안정성이 떨어질 것 같다.
- 복도 2가 랜덤한 위치에 나타나면 미니맵 UI 구성이 어려울 것 같다.
- 복도 1을 길게 만들고 복도 2를 없앨지 고민 중이다.

**해결안: "복도 위치는 고정, 문 뒤 내용만 랜덤"**
- 복도 1과 복도 2의 **실제 위치와 형태는 고정**한다. 복도 2는 맵 다른 곳에 미리 배치해 둔다.
- 복도 1의 8개 문 중 하나에 **"에어락(엘리베이터) 방"** 을 랜덤 배정한다. 에어락에 들어가면 연출(문 닫힘, 흔들림, 암전)과 함께 고정된 복도 2로 이동한다.
- 미니맵은 **고정된 레이아웃 위에 "?" 아이콘**만 표시하고, 연 방부터 아이콘이 드러난다. 복도 2는 에어락을 발견하면 미니맵 탭이 추가된다.
- 결과: 레벨 지오메트리는 항상 같아서 안정적이고, UI도 고정 좌표로 만들 수 있다. 몰입감을 위해 복도 2도 유지할 수 있다.
- 현재 코드(`GeneratePhase2Rooms`: 문 위치 8개에 방 레벨 인스턴스 스트리밍)와 그대로 맞는다.

### 7.2 선택지 데이터 구조 [보완]
현재 `FQuestionStaticData`는 버튼마다 태그 1개 + 값 1개뿐이라 "50% 스택 아니면 50% 체력 -30" 같은 확률 분기를 표현할 수 없다. 아래처럼 바꾼다.

```
선택지(Choice)
 ├─ 표시 문구 (비우면 효과 데이터로 자동 생성)
 └─ 결과 목록 (Outcomes): 가중치로 하나를 뽑음
      ├─ 결과 A (가중치 50) → 효과 목록 [Effect.Stack +1]
      └─ 결과 B (가중치 50) → 효과 목록 [Effect.Stat.Health -30]
```

- 단순 효과: 결과 1개 (가중치 100)
- 7% 즉사: 결과 A(7) = [Effect.Death], 결과 B(93) = [Effect.None]
- 한 결과에 효과 여러 개 가능: [몬스터 3마리, SR 무기 지급]
- 배열이 중첩되어 CSV로는 편집하기 어렵다 → 질문 원본 파일은 **JSON**으로 관리하고 데이터 테이블로 임포트한다.
