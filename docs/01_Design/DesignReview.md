# 초기 기획 리뷰: 부족한 점과 개선 제안

대상: 노션 "프로젝트 기획" (초기 기획 v0.1)
결과 반영: [GDD.md](GDD.md) v0.2의 [보완] 항목

---

## 1. 잘 잡혀 있는 부분
- **"가짜 탈출" 반전**: 페이즈 1 끝에 "축하합니다, 탈출입니다"를 띄웠다가 복도를 보여주는 구조는 이 게임의 가장 강한 훅이다. 그대로 유지한다.
- **물리 버튼**: 화면 클릭이 아니라 몸으로 버튼을 누르는 방식이라 1인칭 몰입감과 잘 맞고, 전투 중에도 버튼을 누르러 가야 하는 긴장을 만들 수 있다.
- **정신력 5단계**: 수치 구간과 효과가 구체적으로 정해져 있다. 패닉에서 질문이 깨지는 아이디어가 좋다.
- **데이터 중심 설계**: 질문, 아이템, 몬스터를 데이터 테이블로 관리하는 방향이 이미 코드에 반영되어 있다.

## 2. 부족한 점

### 2.1 선택에 판단 근거가 없다 (가장 중요)
- 빨강/파랑 중 어느 쪽이 보너스이고 어느 쪽이 패널티인지 모르면 매번 동전 던지기가 된다. 선택형 게임의 재미는 "고민"에서 나오는데, 고민할 정보가 없다.
- **개선**: 질문 유형마다 버튼의 의미를 고정한다 (GDD 2.4).
  - 보너스 = 둘 다 이득, 어떤 이득을 받을지 고른다.
  - 패널티 = 둘 다 손해, 덜 아픈 쪽을 고른다.
  - 밸런스 = 이득과 손해를 맞바꾸는 거래.
  - 유형은 화면 테두리 색으로 보여주고, 패닉 상태에서만 숨긴다.

### 2.2 콘텐츠(질문 문구) 생산 부담이 크다
- 재미가 질문 문구의 양과 질에 달려 있어서, 혼자 개발할 때 끝이 없다. 현재 데이터도 테스트용 5줄에서 멈춰 있다.
- 질문을 한 번 다 보면 다시 할 이유가 줄어든다.
- **개선**
  - **관찰형 질문**: 방 상태(처치한 몬스터 수, 상자 색, 남은 탄약)를 보고 답하는 질문을 템플릿으로 자동 생성한다.
  - **수수께끼(정답형) 유형** 추가: 플레이어 실력이 반영되는 질문.
  - 유형별 최소 수량 목표: 스토리 8 / 보너스 12 / 패널티 12 / 밸런스 10 / 무의미 8 / 수수께끼 10.

### 2.3 "버튼 → 결과"가 정의되어 있지 않다
- 원안에 "보너스와 패널티를 번갈아 받는다"고만 되어 있고, 구체적으로 무슨 일이 일어나는지 없다. "이벤트 종류: 아직 미구상"으로 남아 있다.
- **개선**: 결과를 이벤트 태그로 정의한다 (GDD 7.1). 아이템은 천장 투하구, 몬스터는 천장 스폰구에서 떨어지게 해서 원안의 메인 방 설정을 그대로 활용한다.

### 2.4 스택 규칙이 모호하다
- 답할 때마다 전구가 켜지는지, 보너스일 때만 켜지는지, 패널티면 꺼지는지가 정해져 있지 않다.
- 페이즈 2에서 "방을 여는 기회"와 페이즈 1의 "전구"가 같은 자원인지도 불분명하다.
- **개선**: 스택을 하나의 자원으로 통일하고, 획득·소모 규칙을 표로 정한다 (GDD 2.5).

### 2.5 단말기 위치가 문서 안에서 서로 다르다
- 핵심 시스템에는 "방마다 놓인 질문 모니터", 콘텐츠 설계에는 "메인 방에서 질문"으로 되어 있다.
- **개선**: 메인 단말기 + 보조 단말기 구조로 정리 (GDD 2.3).

### 2.6 페이즈 2 왕복 동선이 지루할 수 있다
- 방을 열려면 메인 방까지 돌아가서 질문에 답하고, 다시 복도 끝 방까지 가야 한다. 복도 2까지 가면 왕복 거리가 길어진다.
- **개선 후보**
  - 복도 2 입구에 보조 단말기 배치.
  - 또는 왕복 자체를 긴장 요소로 쓰기: 이동 중 복도에 몬스터가 순찰.

### 2.7 복도 2 랜덤 배치 우려 (원안에 적힌 고민)
- **개선**: "복도 위치는 고정, 문 뒤 내용만 랜덤" + 에어락 방으로 복도 2 이동 (GDD 5.4). 레벨 안정성과 미니맵 UI 문제를 동시에 해결하고, 복도 2도 유지한다.

### 2.8 실패 조건이 없다
- 체력이 0이 되면 어떻게 되는지, 정신력이 0이 되면 어떻게 되는지 정해져 있지 않다.
- **개선**: 사망 엔딩, 붕괴 엔딩 추가. 재시작 지점은 논의 필요 (GDD 4.3).

### 2.9 진엔딩 조건이 없다
- "숨겨진 문을 열면 진엔딩"만 있고, 문을 찾는 방법이나 여는 조건이 없다.
- **개선**: 기억 조각 3개 + 스토리 질문 일관성 (GDD 4.3). 이미 있는 `EItemType::KeyItem`과 `ChoiceHistory`를 그대로 활용할 수 있다.

### 2.10 세계관의 "누가, 왜"가 비어 있다
- 질문을 내는 존재가 누구인지 없어서, 약 올리는 문구나 반전이 힘을 받기 어렵다.
- **개선**: 관리자 AI "WARDEN"을 화자로 설정 (GDD 1.2). 정신력에 따라 말투가 바뀌면 상태 변화가 연출로도 느껴진다.

### 2.11 정신력 수치 검증이 필요하다
- 시작 80, 답변당 -2 기준으로 계산하면 페이즈 1이 끝날 때까지 두려움 구간에 들어가기 어렵다. 각성(80 이상)은 회복 수단 없이는 도달할 수 없다.
- **개선**: 예상 답변 횟수로 페이스를 계산해 GDD 3.3에 적었다. 회복 수단도 함께 정의했다. 실제 수치는 플레이 테스트 후 조정.

### 2.12 아트 방향과 현재 에셋이 다르다
- 원안은 픽셀 아트인데, 현재 프로젝트는 로우폴리 SF 에셋을 쓰고 있다.
- **개선**: 3D 환경은 그대로 두고, 단말기 UI와 포스트 프로세스(픽셀화, 스캔라인, 글리치)로 픽셀 감성을 낸다.

### 2.13 AttackPower의 의미가 코드 안에서 제각각이다
- 원안: AttackPower = 1을 **배율**로 쓴다.
- 현재 코드:
  - `OecDamageMMC`: 무기 피해 × (1 + AttackPower / 100) → **퍼센트 보너스**로 계산.
  - `OecGA_MonsterAttack`: AttackPower 값을 그대로 피해량으로 사용 → **고정 피해**로 사용.
- **개선**: 원안대로 "최종 피해 = 기본 피해 × AttackPower(기본 1.0)"로 통일한다. 몬스터 기본 피해는 데이터 테이블의 `BaseDamage`를 SetByCaller로 넘기고, AttackPower는 버프·디버프 배율로만 쓴다.

## 3. 추가로 고려하면 좋은 것
| 아이디어 | 효과 | 비용 |
|---|---|---|
| 질문 제한 시간 (페이즈 2, 전투 중) | 긴장감 | 낮음 |
| WARDEN이 가끔 거짓 힌트를 주기 (정신력 낮을 때) | 정신력의 의미 강화 | 중간 |
| 다회차 시 새 스토리 질문 해금 | 반복 플레이 동기 | 중간 |
| 엔딩 도감 / 선택 통계 화면 | 수집 욕구 | 낮음 |
| 관찰형 질문 자동 생성 | 콘텐츠 부담 감소 | 중간 |

## 4. 우선순위 제안
1. **질문 결과 이벤트 연결** (2.3) + **스택 통일** (2.4): 이게 없으면 게임이 돌아가지 않는다.
2. **질문 유형별 버튼 구조** (2.1): 재미의 핵심.
3. **페이즈 1 플레이 가능 상태** 만들기 → 플레이 테스트.
4. 실패 조건, 정신력 효과 (2.8, 2.11).
5. 페이즈 2 에어락 구조와 미니맵 (2.7).
6. 엔딩, 세계관, 연출 (2.9, 2.10, 2.12).
