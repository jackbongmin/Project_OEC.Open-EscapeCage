# 질문지 작성 가이드라인

작성: 2026-11-16 · 버전: v0.2 (주인공 설정 확정, 질문 200개 구성, 몬스터·아이템·이벤트 목록 반영)

이 문서는 질문지를 **대량으로 작성할 때의 기준서이자 작업 지시서**다. 사람이 쓰든 AI가 쓰든 이 문서만 보고 같은 품질·같은 밸런스로 질문을 만들 수 있어야 한다.
관련 문서: [GDD 2.4 질문과 선택지](GDD.md), [ChoiceSystem.md](../02_Tech/ChoiceSystem.md) (데이터 구조·효과 태그)

---

## 0. 세계관 요약 (질문 작성자가 반드시 알아야 할 것)

- **주인공**: 아이를 해친 죄수. 본인은 기억하지 못한다.
- **장소**: 궤도 감옥선 *EscapeCage*. 실제로는 죄수의 의식을 가둔 **처벌 실험 시뮬레이션**이다. 주인공은 이 안에서 같은 고통을 **반복해서** 겪고 있다 (다회차 = 설정 그 자체).
- **WARDEN**: 시뮬레이션을 운영하는 관리자 AI이자 질문의 화자. 차갑고 장난스럽고 존댓말을 쓴다. 주인공의 죄를 전부 알고 있지만 직접 말하지 않고, 질문으로 조금씩 긁는다. 정신력이 낮아질수록 노골적으로 악의적이 된다.
- **질문의 진짜 목적 (설정)**: 탈출 시험이 아니라, 주인공이 자기 죄를 **인정하는지** 관찰하는 실험. 스토리 질문의 선택이 엔딩을 가른다 (11장).

## 1. 질문의 재미: 세 개의 축

| 축 | 플레이어가 느끼는 것 | 해당 질문 |
|---|---|---|
| **판단** | "둘 다 나쁜데 뭐가 덜 나쁘지?", "이 도박 해, 말아?" | 이득·손해·교환·도박·이벤트 질문 |
| **공감** | "ㅋㅋ 이걸 왜 물어봐", "나 하와이안 피자 좋아하는데" | 무의미(밈) 질문 |
| **긁힘** | "...이거 나한테 하는 말인가?" 기억 안 나는 과거를 질문이 건드린다 | 스토리 질문 |

- 버튼 색(빨강/파랑)에는 의미가 없다. 판단 근거는 항상 **화면에 적힌 선택지 문구**다.
- 모든 질문 문장은 WARDEN의 말투로 쓴다.

## 2. 질문 수와 구성

### 2.1 몇 개가 필요한가
| 기준 | 값 | 근거 |

### 2.3 페이즈별 등장 비율 (단말기 `QuestionTypeWeights`)
| 타입 | 페이즈 1 | 페이즈 2 | 이유 |
|---|---|---|---|
| 이득 + 손해 + 교환 + 도박 | 55 | 45 | 페이즈 1은 스택 진행이 우선 |
| 이벤트 | 10 | 15 | 페이즈 2는 전투·생존 압박 |
| 무의미 | 20 | 15 | 긴장 완화 |

- 스택 계산에 쓰는 "효과 질문"은 이득·손해·교환·도박·이벤트를 합친 **65% (페이즈 1)**.

## 4. 가치 환산표 (밸런스의 기준 단위)

모든 효과를 **점수(P)** 하나로 환산해 두 선택지의 무게를 비교한다. 1차 기준값이며 플레이 테스트 후 조정한다.

| 효과 | 태그 | 점수 | 메모 |
|---|---|---|---|
| 스택 +1 | `Effect.Stack` | **+10** | 기준 단위 |
| 체력 +10 | `Effect.Stat.Health` | +2 | |
| 체력 -10 | `Effect.Stat.Health` | -3 | 잃는 쪽을 더 아프게 (손실 회피) |
| 정신력 +5 | `Effect.Stat.Sanity` | +2 | |
| 정신력 -5 | `Effect.Stat.Sanity` | -2 | 답변 1회 기본 -2와 별개 |
| 즉사 1% | `Effect.Death` | -1.5 | 7% ≈ -10.5 ≈ 체력 -30(-9) |
| 몬스터 | `Effect.Spawn.Monster` | 3.1 표 | |
| 아이템 | `Effect.Give.Item` | 3.2 / 3.3 표 | |
| 지속: 답변마다 1% 스택 | `Effect.Passive.AnswerStackChance` | +2 | 남은 답변 약 20회 × 1% |
| 방 어두워짐 (답변 3회) | `Effect.Env.Darken` | -3 | |
| 이벤트 | `Effect.Event.Start` (신규) | 5장 표 | |
| 아무 일 없음 | `Effect.None` | 0 | |

**확률 결과 점수 = 각 결과 점수 × 확률의 합 (기대값)**
- 예 (사용자 원안): 40% 회복 주사 / 60% 걷는 좀비 1마리 → 0.4 × 5 + 0.6 × (-2) = **+0.8**

### 4.1 카테고리별 짝 맞추기 규칙
| 카테고리 | 규칙 | 예 (빨강 vs 파랑) | 점수 |
|---|---|---|---|
| 무조건 이득 | 둘 다 **+**, 차이 3P 이하, 성격이 다른 보상 | 회복 주사 vs 권총 탄약 2묶음 + 응급 붕대 | +5 vs +6 |
| 무조건 손해 | 둘 다 **-**, 차이 3P 이하 | 체력 -30 vs 7% 즉사 | -9 vs -10.5 |
| 교환 | 기대값 차이 3P 이하, 한쪽은 득+실, 다른 쪽은 다른 득+실 | 스택 +1 + 골렘 R vs 의료 키트 + 방 어두워짐 | +5 vs +6 |
| 도박 | 한쪽은 **안전**(아무것도 안 함 / 작은 확정), 다른 쪽은 **확률 분기**. 기대값 차이 4P 이하 | 아무것도 안 함 vs 40% 회복 주사 / 60% 걷는 좀비 | 0 vs +0.8 |
| 이벤트 | 한쪽 이상이 이벤트. 점수는 "평균 실력" 기준 | 튀는 구체 5개 vs 체력 -15 | -4.5 vs -4.5 |

**도박 질문의 세부 유형** (32개를 아래처럼 나눈다)
| 유형 | 비율 | 예 |
|---|---|---|
| 소박한 도박 (안전 = 아무것도 안 함) | 40% | 아무것도 안 함 vs 40% 아이템 / 60% 몬스터 |
| 큰 도박 (낮은 확률 대박) | 25% | 응급 붕대 vs 10% 라이플 SR / 90% 체력 -15 |
| 스택 도박 | 25% | 확정 체력 +10 vs 50% 스택 +1 / 50% 체력 -30 |
| 죽음의 도박 | 10% | 체력 -25 vs 5% 즉사 / 95% 아무 일 없음 (페이즈 2 전용, 즉사 최대 10%) |

**스택은 귀하게** (6장 기준)
- 스택 선택지는 **질문 5개에 1번** 보일 정도로만 (전체 질문의 약 20%).
- 스택은 대부분 **대가나 확률과 함께** 준다: "스택 +1 + 골렘 R", "60% 스택 / 40% 체력 -25". **공짜 확정 스택**은 스택 질문의 10% 이하 (튜토리얼 제외).
- 한 질문에 스택을 양쪽 다 주지 않는다 (예외 없음).
- 스택 +2 이상은 쓰지 않는다.

**공통 금지 사항**
- 같은 성격끼리 붙이지 않기 (체력 -10 vs 체력 -20은 고민이 없다).
- 즉사는 최대 10%. 페이즈 1은 5% 이하.

## 5. 이벤트 목록 (구현 가능한 것만)

방식: `Effect.Event.Start` + `Param` = 이벤트 ID → `DT_RoomEvent`에서 이벤트 액터 클래스·지속 시간·성공/실패 효과를 찾아 메인 방에 생성한다. 성공/실패 보상은 **선택지 효과 구조(`FOecChoiceEffect`)를 그대로 재사용**한다.

| ID | 이름 | 내용 | 시간 | 성공 조건 → 보상 | 위험 | 점수 | 구현 방식 | 난이도 |
|---|---|---|---|---|---|---|---|---|
| `Event_BouncingOrbs` | 튀는 구체 | 에너지 구체 5개가 벽에 튕기며 날아다님. 닿으면 체력 -5 | 30초 | (보상형) 끝까지 버티면 스택 +1 | 평균 3회 피격 = -15 | -4.5 / 보상형 +3 | 구체 액터 + `ProjectileMovement`(반사) + 오버랩 피해 GE | 쉬움 |
| `Event_RisingPillar` | 피난 기둥 | 바닥에서 기둥이 솟음. 위에 올라가면 몬스터가 못 닿음 | 20초 후 내려감 | - | - | +3 | 타임라인으로 기둥 이동. 몬스터 소환과 **같이** 쓰는 이벤트 | 쉬움 |

| `Event_LowGravity` | 중력 이상 | 중력이 약해져 높이 뜀 | 30초 | - | 조작 혼란 | 0 | `GravityScale` 버프 GE | 쉬움 |
| `Event_SupplyDefense` | 보급 상자 방어 | 잠긴 상자가 떨어지고 좀비가 몰려옴. 30초 버티면 상자가 열림 | 30초 | 생존 → 무기 R 또는 의료 키트 | 걷는 좀비 4마리 | +3 | 상자 액터 + 타이머 + 기존 소환 | 보통 |
| `Event_LaserSweep` | 레이저 스윕 | 바닥 높이 레이저 막대가 회전. 점프로 넘기 | 20초 | 무피격 시 스택 +1 | 닿으면 체력 -10 | +2 | 회전 액터 + 오버랩 피해 | 보통 |
| `Event_ElectricFloor` | 전기 바닥 | 바닥 타일 절반이 번갈아 감전 (불이 들어온 타일 피하기) | 20초 | 무피격 시 회복 주사 | 밟으면 체력 -8 | -1 | 타일 액터 배열 + 머티리얼 교체 (전구와 같은 방식) | 보통 |
| `Event_Turret` | 천장 터렛 | 천장 터렛이 플레이어를 조준 사격. 엄폐 벽과 함께 등장 | 20초 | 터렛 파괴 시 라이플 탄약 2묶음 | 초당 피해 | -1 | 터렛 액터 (몬스터 AI 재사용 가능) | 보통 |
| `Event_PressurePlates` | 압력판 퍼즐 | 바닥에 압력판 3개. 단말기에 나온 순서대로 밟기 | 30초 | 성공 시 스택 +1 | 실패 시 정신력 -10 | +4 | 압력판 액터 + 순서 검사 | 보통 |

- **이벤트 질문 작성 규칙**
  - 페이즈 1: "쉬움" 이벤트만, 시간 30초 이하.
  - **조합 이벤트**를 적극 쓴다: "좀비 3마리 + 피난 기둥", "골렘 R + 엄폐 벽", "튀는 구체 + 정전". 효과 목록에 여러 개를 넣으면 된다.
  - 이벤트끼리 비교도 좋다: "튀는 구체 vs 낙하 잔해" (둘 다 손해지만 종류가 다른 고통).
  - 보상형 이벤트는 "버티면 스택"처럼 **실력으로 기대값을 올리는** 선택지다.

## 6. 페이즈 1 스택 밸런스 (시뮬레이션)

원칙: **스택은 귀하다.** 스택 선택지가 자주 나오면 랜덤의 재미가 사라진다. 대신 **처음 1개는 튜토리얼에서 확정**으로 줘서 "전구가 켜지는 맛"을 먼저 알려준다.

목표: 전구 5개를 **평균 21회 답변**에 채우고, 운이 나빠도 32회 안에 끝나게 한다.

조건: 튜토리얼 3문항에서 스택 1개 확정 → 남은 4개를 랜덤 질문으로. 플레이어가 스택 쪽을 고르는 비율 85% 가정. 스택 보정 = N번 연속 스택을 못 얻으면 다음 질문에 **확정 스택** 선택지 보장.

| 질문당 스택 선택지 등장 | 평균 성공 확률 | 보정 N | 평균 답변 수 | 90% 플레이어 | 최악 | 보정 발동 (판당) |
|---|---|---|---|---|---|---|
| (이전안) 46% | 80% | 3 | 12.5 | 16 | 22 | - |
| 29% | 70% | 5 | 18.7 | 24 | 30 | 1.6회 |
| 20% | 70% | 4 | 18.9 | 23 | 26 | 2.5회 |
| **20%** | **70%** | **5** | **21.0** | **26** | **32** | **2.2회** |
| 20% | 70% | 6 | 22.8 | 29 | 34 | 2.0회 |

(몬테카를로 2만 회, 2026-11-16. 튜토리얼 3문항 포함. 플레이 테스트 전 예상값)

- **채택: 질문당 스택 등장 약 20% (효과 질문 65% × 그중 31%) · 평균 성공 70% · 보정 5회 · 튜토리얼 스택 1개.**
  - 체감: 질문 5개에 한 번 스택 기회가 보이고, 그마저 대가나 확률이 붙어 있다.
  - 보정은 한 판에 2번 정도 몰래 작동한다 (최악의 늘어짐만 막음). 보정을 4회로 당기면 평균 18.9회지만 보정이 너무 자주 개입해 "랜덤"이 아니라 "정해진 간격"처럼 느껴질 수 있다.
- 작성 기준으로 바꾸면: 효과 질문(이득·손해·교환·도박·이벤트 140개) 중 **약 43개에만 스택 결과**를 넣고, 스택 결과의 확률 평균이 **70%**가 되게 한다.
  - 확정 100%는 대가와 함께 ("스택 +1 + 골렘 R"), 확률형은 50~70% ("60% 스택 / 40% 체력 -25").
- 손해 질문의 스택: "체력 -30 + 스택 +1 vs 정신력 -15"처럼 **"아파도 진행할래?"** 구조.
- **정신력 조정 제안**: 페이즈 1이 21회로 길어지므로 답변당 -2를 유지하면 페이즈 1 끝에 약 38까지 떨어진다. **페이즈 1은 답변당 -1, 페이즈 2부터 -2**를 권장한다 (페이즈 1 종료 약 59). > 논의 필요 (GDD 3.2)

## 7. 체력·정신력 예산
| 구간 | 체력 순변화 목표 | 정신력 목표 | 메모 |
|---|---|---|---|
| 페이즈 1 (21회) | 평균 -40 (질문 -25 + 전투 -15), 회복 포함 | 80 → 약 59 (답변당 -1 적용 시) | 페이즈 1 사망 확률 5% 이하 |
| 페이즈 2 (15회) | 평균 -60, 회복템으로 메움 | 55 → 약 20 | 두려움~공포 구간, 회복템 탐색 동기 |

- 효과 질문 전체의 **평균 점수는 0 ~ +1P** (이득과 손해가 대략 상쇄, 스택이 있어 체감은 약간 이득).
- 스토리 질문은 정신력을 주로 깎는다 (-5 ~ -10). 스토리 질문이 많은 페이즈 2에서 정신력 압박이 커지는 것이 의도다.

## 8. 카테고리별 작성 규칙

### 8.1 효과 질문 (이득·손해·교환·도박)
- 선택지 문구는 **비워둔다** (`DisplayText: ""`) → 효과 데이터로 자동 생성 ("체력 10 회복", "40% 확률로 ...").
  - 단, "아무것도 하지 않는다", "그냥 지나간다" 같은 안전 선택지는 직접 쓴다.
- 질문 문장은 카테고리마다 WARDEN 말투 변형을 돌려 쓴다 (각 10종 이상).
  - 이득: "오늘은 기분이 좋군요. 고르십시오." / "착한 피험자에게 주는 선물입니다."
  - 손해: "고통에도 종류가 있습니다." / "어느 쪽이 덜 아플지는 당신이 더 잘 알겠죠."
  - 교환: "공짜는 없습니다." / "무언가를 얻으려면 무언가를 내놓아야죠."
  - 도박: "운을 시험해 보죠." / "당신은 운이 좋은 편입니까?"

### 8.2 무의미 (밈) 질문
- 효과 없음 (`Outcomes: []`), 선택만 기록.
- 좋은 무의미 질문: ① 누구나 즉답할 수 있는 사소한 취향 ② 답이 50:50으로 갈려 논쟁이 되는 것 ③ 질문 자체가 이상한 것 ("당신은 지금 숨을 쉬고 있습니까?").
- 40개 중 **약 6개는 무의미한 척하는 스토리 떡밥**: "놀이터를 좋아합니까?", "비 오는 날을 좋아합니까?" → 스토리 갈래 B와 연결, `StoryTag` 기록.

### 8.3 이벤트 질문
- 5장 이벤트 표의 ID만 사용한다 (새 이벤트를 지어내지 않는다).
- 24개 = 12종 이벤트 × 평균 2회 (단독, 조합, 이벤트끼리 비교).

### 8.4 스토리 질문 (연쇄)
**원칙**
1. **직접 말하지 않는다.** "당신은 아이를 해쳤습니다"가 아니라, 질문의 전제로 슬쩍 깐다.
2. **앞 선택이 다음 질문을 바꾼다.** 갈래마다 도입 → 분기(2개) → 확인의 4노드.
3. **어느 쪽을 골라도 긁힌다.** 정답이 없다.
4. **묘사하지 않는다.** 폭력·피해를 구체적으로 그리지 않는다. 공포는 암시와 상상에서 나온다.
5. 효과는 주로 **정신력** (-5 ~ -10). "인정" 선택지에 가끔 작은 보상 (WARDEN이 칭찬하는 불쾌함).
6. 모든 선택지에 `StoryTag`: `Admit`(인정) / `Deny`(부정) / `Avoid`(회피).

**갈래 구조 (4노드)**
```
[X1 도입] 평범한 질문처럼 보임
   ├─ 빨강 → [X2a 찌르기] 전제가 드러남
   └─ 파랑 → [X2b 찌르기] 다른 방향에서 드러남
                 └→ [X3 확인] (X2a/X2b 중 하나를 본 뒤, 다음 페이즈 이후) 인정할지 묻기
```

**예시 갈래 A: "선택"**
```
[A1] "반드시 한 명을 죽여야 한다면, 누구를 고르겠습니까?"   어린이 / 어른
[A2a] (어린이) "망설임이 없군요. 처음이 아니라서입니까?"        그렇다(Admit) / 아니다(Deny)
[A2b] (어른)   "그렇군요. 그럼 그때는 왜 아이를 골랐습니까?"   기억나지 않는다(Avoid) / 그건 내가 아니다(Deny)
[A3]  "그 아이의 이름을 기억합니까?"                           기억한다(Admit, 정신력 -10) / 모른다(Deny, 정신력 -5)
```
- A2b가 핵심이다. 플레이어는 "어른"을 골랐는데 WARDEN은 "그때는 왜 아이를"이라고 되묻는다. 고른 것은 플레이어가 아니라 **과거의 주인공**이다.

**6갈래**
| 갈래 | 제목 | 도입의 위장 | 건드리는 것 | 등장 |
|---|---|---|---|---|
| A | 선택 | 트롤리 문제 같은 윤리 질문 | 피해자가 아이였다는 것 | 페이즈 1 |
| B | 그날 | 날씨, 놀이터, 오후 시간 같은 일상 취향 | 사건 당일의 장면 | 페이즈 1 |
| C | 재판 | 정의, 처벌에 대한 의견 | 법정, 판결, 형량 | 페이즈 2 |
| D | 가족 | "누군가 당신을 기다립니까?" | 피해자의 부모, 주인공의 가족 | 페이즈 2 |
| E | 반복 | "이 방, 낯익지 않습니까?" | 시뮬레이션, 몇 번째 반복인지 (다회차) | 페이즈 2, 2회차 이상 우대 |
| F | 속죄 | "벌은 언젠가 끝나야 합니까?" | 용서, 대가, 인정 | 페이즈 2 후반 |

## 10. JSON 작성 규칙

```json
{
	"Name": "Q_GB_001",
	"QuestionID": "Q_GB_001",
	"QuestionType": "Gamble",
	"QuestionText": "운을 시험해 보죠.",
	"AllowedPhases": [1, 2],
	"bEnabled": false,
	"RedChoice": {
		"DisplayText": "아무것도 하지 않는다",
		"Outcomes": []
	},
	"BlueChoice": {
		"DisplayText": "",
		"Outcomes": [
			{ "Weight": 40, "Effects": [ { "EffectTag": { "TagName": "Effect.Give.Item" }, "Value": 1, "Param": "Heal_M" } ] },
			{ "Weight": 60, "Effects": [ { "EffectTag": { "TagName": "Effect.Spawn.Monster" }, "Value": 1, "Param": "Zombie_Walker" } ] }
		]
	},
	"BalanceNote": "Red 0 / Blue +0.8"
}
```
- 신규 필드: `AllowedPhases`, `RequiredChoices`, `MinRunCount`, `FixedOrder`, `bEnabled`, `StoryTag`(선택지 안), `BalanceNote`(검수용 메모, 게임에서 안 씀). 기능 구현 전에는 임포트 시 무시된다.
- 예정 코드(3장 "예정")를 하나라도 쓰면 `bEnabled: false`.
- ID 규칙: `Q_<분류>_<3자리 번호>`, 스토리는 `Q_ST_<갈래><노드>` (`Q_ST_A2b`).
- `Name`과 `QuestionID`는 항상 같게.
- 문구 길이: 질문 문장 40자 이내, 선택지 12자 이내.

## 11. 엔딩과 스토리 성향
| 엔딩 | 조건 (안) | 의미 |
|---|---|---|
| 진엔딩 | 기억 조각 3개 + 스토리 선택 중 `Admit`이 가장 많음 | 죄를 인정 → 시뮬레이션이 멈춘다 (혹은 다음 단계의 벌이 시작된다) |
| 노말 엔딩 | 탈출 방 도달 | "탈출했습니다" → 화면이 꺼졌다 켜지며 메인 방에서 다시 깨어남 (루프) |
| 사망 엔딩 | 체력 0 | WARDEN: "다시 시작합니다." |
| 붕괴 엔딩 | 정신력 0 | 기억이 한꺼번에 밀려와 무너짐 (가장 직접적인 암시) |

> 논의 필요: 진엔딩의 마지막 장면 (구원인지, 더 깊은 벌인지)

## 12. 검수 체크리스트
- [ ] 두 선택지의 점수 차이가 4.1 규칙 안인가 (`BalanceNote`에 계산을 적었는가)
- [ ] 같은 성격끼리 붙이지 않았는가
- [ ] 페이즈 1: 위협도 3 이하 몬스터, 즉사 5% 이하, 쉬운 이벤트만
- [ ] WARDEN 말투 (존댓말, 차갑고 장난스러움)
- [ ] 스토리: 직접 말하지 않음, 묘사 없음, 모든 선택지에 `StoryTag`
- [ ] 코드가 3장·5장 목록에 있는 것인가, 예정 코드면 `bEnabled: false`
- [ ] 문구 길이 제한
- [ ] 묶음 전체: 효과 질문의 **31%**(약 43개)에만 스택 결과, 스택 확률 평균 **70%**, 공짜 확정 스택은 스택 질문의 10% 이하, 효과 질문 평균 점수 0 ~ +1P

### 13.2 프롬프트
```
docs/01_Design/QuestionGuideline.md를 처음부터 끝까지 읽고, 그 문서를 유일한 기준으로 OEC 게임의 질문지를 작성해줘.
참고 문서: docs/01_Design/GDD.md, docs/02_Tech/ChoiceSystem.md, ProjectData/QuestionStaticData.json (기존 형식 예시)

이번 작업: 배치 [번호] (13.1 표 참고)

규칙
1. 형식은 가이드라인 10장 JSON 규칙을 그대로 따른다. 질문마다 BalanceNote에 두 선택지의 점수 계산을 적는다.
2. 몬스터·아이템·이벤트 코드는 가이드라인 3장·5장 목록에 있는 것만 쓴다. 예정 코드를 쓰면 bEnabled: false.
3. 4.1 짝 맞추기 규칙과 "스택은 귀하게" 규칙, 6장 스택 비율(효과 질문의 31%, 약 43개에만 스택, 스택 확률 평균 70%, 공짜 확정 스택 10% 이하), 페이즈 제한을 지킨다. 스택이 너무 자주 보이면 랜덤의 재미가 사라진다는 점을 최우선으로 한다.
4. 질문 문장과 선택지 문구는 WARDEN 말투, 길이 제한(질문 40자, 선택지 12자)을 지킨다.
5. 스토리 질문은 8.4의 원칙(직접 말하지 않기, 묘사하지 않기, 어느 쪽이든 긁히기, StoryTag)을 지킨다.
6. 다 쓴 뒤 12장 체크리스트로 스스로 검수하고, 배치 요약(개수, 카테고리별 평균 점수, 스택 포함 비율, 스택 평균 확률)을 마지막에 보고한다.
7. 소스 코드는 수정하지 않는다. 출력 파일만 만든다.
```
