# TS-002: 페이즈 1 스택이 쌓이지 않아 페이즈 2로 넘어가지 않는 문제

| 항목 | 내용 |
|---|---|
| 분류 | 버그 / 구조 |
| 관련 시스템 | 서브시스템 간 이벤트 흐름 (`UOecEventSubsystem`, `UOecStageManagerSubsystem`), 문 액터 |
| 발견일 / 해결일 | 2026-11-13 / 2026-11-14 |
| 관련 커밋 | `cc761e8` |

## 1. 문제
- 게임 흐름: 페이즈 1에서 질문에 답해 전구(스택) 5개를 켜면 메인 방 문이 열리고 페이즈 2로 넘어가야 한다.
- 실제로는 버튼을 아무리 눌러도 **페이즈가 바뀌지 않았다.** 대신 페이즈 2용 문 열쇠 스택만 늘어났다.

## 2. 원인 분석
- 스택 값이 두 군데에 있었다.
  - `UOecStageManagerSubsystem::CurrentStack`: 페이즈 1 전구 (최대 5, 다 차면 `ChangePhase`)
  - `UOecEventSubsystem::PlayerStacks`: 페이즈 2 문 열쇠 (문을 열 때 소모)
- C++ 전체와 블루프린트 에셋(`.uasset` 이름 테이블)에서 `AddStack`, `ChangePhase`, `OnPhaseChanged`를 호출하는 곳을 검색했다 → **호출하는 곳이 하나도 없었다.**
- git 히스토리로 언제 끊겼는지 추적했다.

| 커밋 | 날짜 | 변화 |
|---|---|---|
| `0724de8` | 04-06 | 질문 결과 처리에서 `StageManager->AddStack()` 호출 → 연결됨 |
| `03650d6` | 04-06 | "다음 질문 넘어가기" 리팩토링 중 **호출이 삭제됨** |
| `6d78dde` | 04-08 | 페이즈 2 문을 만들며 `PlayerStacks` 추가 → 모든 스택이 여기로만 감 |

- 두 스택을 나눈 설계 의도(전구는 누적, 열쇠는 소모)는 맞았고, **리팩토링 중 연결 한 줄이 빠진 것**이 원인이었다. 컴파일 에러도, 런타임 에러도 나지 않아서 발견이 늦었다.

## 3. 해결
- 설계 의도대로 두 스택은 유지하고, 질문 결과를 **현재 페이즈에 맞는 스택으로 라우팅**했다.

```cpp
// OecEventSubsystem.cpp
if (InTag == OecGameplayTags::Event_Stack_Add)
{
	UOecStageManagerSubsystem* stageManager = GetGameInstance()->GetSubsystem<UOecStageManagerSubsystem>();

	if (stageManager && stageManager->GetCurrentPhase() == EOecGamePhase::Phase1_MainRoom)
	{
		// 페이즈 1: 전구 스택 (소모되지 않음, 다 차면 페이즈 2로 전환)
		stageManager->AddStack((int32)InValue);
	}
	else
	{
		// 페이즈 2: 문 열쇠 스택 (닫힌 방 문을 열 때 소모)
		ModifyStacks((int32)InValue);
	}
}
```

- 메인 방 문은 서브시스템이 직접 찾아 여는 대신, 문이 `OnPhaseChanged` 델리게이트를 **구독**하게 했다. 서브시스템(상위 규칙)이 특정 액터 클래스를 몰라도 되고, 페이즈 전환에 반응하는 액터를 더 추가해도 서브시스템을 고칠 필요가 없다.
  - 레벨 스트리밍으로 페이즈 2 이후에 로드되는 경우를 위해 `BeginPlay`에서도 현재 페이즈를 한 번 확인한다.

## 4. 전후 비교
측정 조건: **코드 경로 기준 (에디터 플레이 검증 대기)**. 페이즈 1에서 `Event.Stack.Add`(값 1) 결과를 5번 선택했을 때.

| 지표 | 전 | 후 |
|---|---|---|
| 페이즈 1 전구 스택 | 0 / 5 | 5 / 5 |
| 페이즈 2 열쇠 스택 증가량 | +5 (잘못 적립) | 0 |
| 페이즈 전환 발생 | 0회 | 1회 |
| 메인 방 문 개방 | 안 됨 | 자동 개방 |
| `AddStack` / `OnPhaseChanged` 호출처 | 0곳 | 각 1곳 |

## 5. 배운 점
- 이벤트(델리게이트)로 연결된 흐름은 끊겨도 에러가 나지 않는다. 핵심 흐름(페이즈 전환)은 치트 커맨드나 자동 테스트로 빠르게 확인할 수 있어야 한다 → 로드맵 M1의 치트 커맨드로 반영.
- 비슷한 이름의 값이 두 개 있으면 역할을 문서와 주석에 명시한다 (전구 / 열쇠).
