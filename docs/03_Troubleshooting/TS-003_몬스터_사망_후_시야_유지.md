# TS-003: 몬스터가 죽어도 시야(감지·디버그 원뿔)가 남는 문제

| 항목 | 내용 |
|---|---|
| 분류 | 버그 / 구조 |
| 관련 시스템 | AI (Perception, BT), 오브젝트 풀링 |
| 발견일 / 해결일 | 2026-11-16 / 2026-11-16 (에디터 검증 대기) |
| 관련 커밋 | (커밋 후 기입) |

## 1. 문제
- 골렘을 죽이면 시체가 7초 동안 남는데, 그동안 **시야 디버그 원뿔이 계속 그려진다.** 풀에 반납돼 숨겨진 뒤에도 원뿔이 남는다.
- 재현: 골렘 소환(`OecSpawnMonster Golem_N 1`) → 사살 → 시체 위치에 초록/빨강 원뿔이 남는다.

## 2. 원인 분석
- 원뿔은 `AOecAIController::Tick`에서 `GetPawn()`이 있으면 매 프레임 그린다. 컨트롤러는 몬스터가 죽었는지 모른다.
- 사망 처리(`AOecMonsterBase::Die`)는 BT만 멈추고(`StopLogic`), **Perception과 Tick은 그대로** 뒀다. 그래서
  1. 원뿔이 계속 그려지고,
  2. 시야 감지도 살아 있어 `OnTargetDetected`가 블랙보드 `TargetActor`를 다시 채울 수 있었다.
- 몬스터가 컨트롤러의 BrainComponent를 직접 꺼내 조작하고 있어, AI 상태를 켜고 끄는 코드가 몬스터(사망·풀 활성화)에 흩어져 있었다.
```cpp
// 문제 코드 (OecMonsterBase::Die)
if (AAIController* aiController = Cast<AAIController>(GetController()))
{
	if (UBrainComponent* brain = aiController->GetBrainComponent())
	{
		brain->StopLogic("Monster Died");   // BT만 정지. 시야 감지·Tick(디버그 원뿔)은 계속 동작
	}
}
```

## 3. 해결
- **몬스터는 상태만 알리고, AI 처리는 컨트롤러가 맡는다.**
  - `AOecMonsterBase`에 `OnMonsterActiveChanged(몬스터, bInActive)` 델리게이트 추가. 사망·풀 반납 때 false, 풀에서 다시 꺼낼 때 true를 한 번씩만 발행한다.
  - `AOecAIController`가 빙의할 때 구독하고, `SetPerceptionActive`에서 시야 감지(`SetSenseEnabled` + `ForgetAll`), 블랙보드 대상, BT, 이동, 디버그 Tick을 한 번에 켜고 끈다.
- 다른 선택지와 비교
  - Tick 안에서 `IsDead()` 검사: 원뿔은 사라지지만 감지와 Tick은 계속 돈다. 컨트롤러가 몬스터 상태를 매 프레임 묻는 구조가 된다.
  - 사망 시 컨트롤러 `UnPossess`: 풀에서 재사용할 때 다시 빙의·BT 초기화가 필요해 풀링 이점이 줄어든다.
```cpp
// 수정 코드 (OecAIController)
void AOecAIController::SetPerceptionActive(bool bInActive)
{
	if (bIsPerceptionActive == bInActive) return;
	bIsPerceptionActive = bInActive;

	PerceptionComponent->SetSenseEnabled(UAISense_Sight::StaticClass(), bInActive);
	if (!bInActive) PerceptionComponent->ForgetAll();
	// 블랙보드 대상 초기화, BT 정지/재시작, StopMovement, 디버그 Tick on/off
}
```

### 같이 정리한 풀링 연결
| 위치 | 문제 | 수정 |
|---|---|---|
| `UOecPoolingSubsystem::ActorPool` | `UPROPERTY`가 아닌 원시 포인터 맵이라, 레벨 언로드 등으로 파괴된 액터를 `IsValid`로 검사하면 해제된 메모리를 읽을 수 있음 | `FOecActorPoolList` 구조체로 감싸 `UPROPERTY` 맵으로 변경 |
| `ReturnToPool` | 같은 액터를 두 번 반납하면 풀에 두 번 들어가, 이후 한 액터가 두 곳에 소환됨 | 이미 풀에 있으면 경고 후 무시 (`DeactivateAndStore`) |
| `ReturnAllActiveActors` | 반납 로직이 `ReturnToPool`과 복사돼 있음 | `DeactivateAndStore`로 통일 |
| 몬스터 사망 | 진행 중이던 공격 어빌리티, 이동이 그대로 | `CancelAllAbilities`, `DisableMovement` |
| 몬스터 풀 반납/재사용 | 사망 타이머가 남아 재사용 직후 다시 반납될 수 있음, 숨겨진 상태에서 이동 컴포넌트 Tick | 타이머 해제, 이동 컴포넌트 Tick 끄기/켜기, 재사용 시 `MOVE_Walking` 복구 |

## 4. 전후 비교
측정 조건: 미측정 (에디터 검증 대기)

| 지표 | 전 | 후 | 변화 |
|---|---|---|---|
| 사망 후 원뿔 표시 | 남음 | 사라짐 (예상) | 에디터 확인 필요 |
| 죽은 몬스터 컨트롤러 Tick | 매 프레임 | 꺼짐 | |

## 5. 배운 점
- 폰의 생사 같은 상태 변화는 폰이 델리게이트로 알리고, 컨트롤러·UI가 구독해 각자 정리한다. 폰이 컨트롤러 내부(BrainComponent)를 직접 만지지 않는다.
- 풀링 대상은 "꺼질 때 멈춰야 할 것"(타이머, 어빌리티, 이동, 감지, Tick)을 한 곳에서 모두 끈다.
